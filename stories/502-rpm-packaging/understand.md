# SPEC-502: RPM Packaging — Gap Analysis

## Current State

The project already has several packaging-related artifacts in place:

**Systemd units** — present at `dist/systemd/netfyr.service` and `dist/systemd/netfyr.socket`. The content matches the spec exactly (Type=notify, RuntimeDirectory=netfyr, StateDirectory=netfyr, ListenStream=/run/netfyr/netfyr.sock, SocketMode=0666).

**Man pages** — five pages exist under `man/`:
- `man/netfyr.1`, `man/netfyr-apply.1`, `man/netfyr-query.1` (generated by xtask)
- `man/netfyr.yaml.5` (YAML reference, hand-maintained)
- `man/netfyr-examples.7` (examples, hand-maintained)

**Man page generator** — `xtask/src/main.rs` implements `cargo run -p xtask -- man` which generates the section-1 pages from clap definitions and leaves the hand-maintained pages untouched.

**Binaries** — `netfyr` (CLI) and `netfyr-daemon` (daemon) are built from `crates/netfyr-cli` and `crates/netfyr-daemon` respectively.

**Workspace `Cargo.toml`** — exists at repo root with all members. No version field is present at the workspace level; version lives in individual crate manifests.

**`.gitignore`** — currently only ignores `/target`. The `vendor/` directory is not listed.

**Missing entirely:**
- `netfyr.spec` — no RPM spec file exists anywhere in the project
- `scripts/build-rpm.sh` — no build script exists
- `examples/` directory — referenced in the spec's `%install` section but absent from the project tree
- `LICENSE` file — referenced by `%license LICENSE` in the spec but absent from the project root
- `/vendor` entry in `.gitignore`

## Requirements

### Files to create

1. **`netfyr.spec`** at workspace root — RPM spec file producing two packages (`netfyr` and `netfyr-daemon`), using `%cargo_build` / `%cargo_prep` macros from `rust-packaging`.

2. **`scripts/build-rpm.sh`** — shell script that reads `Name` and `Version` from the spec, creates the source tarball via `git archive`, creates the vendor tarball via `cargo vendor`, copies the spec to `~/rpmbuild/SPECS/`, and invokes `rpmbuild -ba`. Must be executable (mode 0755).

3. **`examples/policies/`** directory with at least one example YAML policy file (e.g., `bare-ethernet.yaml`), because the spec's `%install` section installs `examples/policies/*.yaml` and the `%check` section will fail if the glob expands to nothing.

4. **`LICENSE`** file at workspace root — required by `%license LICENSE` in both `%files` sections.

5. **`.gitignore` update** — add `/vendor` to prevent accidental commits of the vendored dependency tree.

### Spec file technical requirements

- `Name: netfyr`, `Version: 0.1.0`, `Release: 1%{?dist}`
- `Source0`: source tarball, `Source1`: vendor tarball
- `ExclusiveArch: %{rust_arches}`
- `BuildRequires`: `cargo >= 1.86`, `rust >= 1.86`, `rust-packaging >= 25`, `systemd-rpm-macros`
- `%prep`: `%autosetup`, extract vendor tarball, call `%cargo_prep -v vendor`
- `%build`: `%cargo_build`, then `cargo run -p xtask -- man` (not `cargo xtask man`)
- `%install`: install both binaries (0755), man pages by section, systemd units via `%{_unitdir}`, config dirs, example files; do **not** manually install LICENSE
- `%check`: smoke-test both binaries with `--help`
- `%post`/`%preun`/`%postun` scriptlets on the daemon subpackage using `%systemd_post`, `%systemd_preun`, `%systemd_postun_with_restart`
- `%files netfyr`: LICENSE via `%license`, binary, man pages (sections 1/5/7), config dirs (`%dir`), example docs
- `%files netfyr-daemon`: LICENSE via `%license`, daemon binary, both systemd units
- Macro names in comments must be escaped as `%%macro_name`

### Systemd unit path discrepancy

The spec references `dist/netfyr.service` and `dist/netfyr.socket` (flat `dist/` directory), but the actual files reside at `dist/systemd/netfyr.service` and `dist/systemd/netfyr.socket`. Either the spec's `Source` paths or the file locations must be reconciled.

## Integration Points

- **`xtask`**: The `%build` section invokes `cargo run -p xtask -- man`, which must be invoked after `%cargo_prep` (which may overwrite `.cargo/config.toml`). The xtask binary uses `CARGO_MANIFEST_DIR` at compile time to locate the `man/` output directory relative to `xtask/` — this works correctly from the build root.

- **`netfyr-cli/src/main.rs`** and **`netfyr-daemon/src/main.rs`**: Both binary entry points must respond to `--help` for the `%check` smoke-test.

- **Cargo workspace `Cargo.toml`**: The version string in `netfyr.spec` (`Version: 0.1.0`) must stay in sync with the version declared in the individual crate `Cargo.toml` files. The build script extracts the version from the spec; there is no automated sync mechanism.

- **`dist/systemd/` vs `dist/`**: The spec (as written in the story) references `dist/netfyr.service` and `dist/netfyr.socket` without the `systemd/` subdirectory. The actual files are one level deeper. Implementer must decide: move files to `dist/` flat, or reference `dist/systemd/` in the spec.

- **`rust-packaging` macros**: The `%cargo_prep -v vendor` invocation requires the vendor tarball to be extracted before calling it. The `%cargo_build` macro drives the actual Rust compilation. The build system (Koji/mock) must have `rust-packaging >= 25` installed.

## Risks

1. **Missing `LICENSE` file**: The spec's `%license LICENSE` directive in both `%files` sections will cause `rpmbuild` to fail if there is no `LICENSE` file at the project root. This must be created before any build attempt.

2. **Empty `examples/policies/` glob**: The `install -pm 0644 examples/policies/*.yaml` line in `%install` will cause the shell to emit an error (glob expands to nothing) if no `.yaml` files exist in that directory. At least one example file is mandatory.

3. **Systemd unit path mismatch**: Files are at `dist/systemd/netfyr.{service,socket}` but the spec template references `dist/netfyr.{service,socket}`. Building without resolving this will fail at `%install` with "file not found".

4. **Workspace version drift**: The version in `netfyr.spec` (`Version: 0.1.0`) and in individual `Cargo.toml` files can diverge. There is no enforced synchronization. The build script parses the spec's version, not the Cargo manifests.

5. **`%cargo_prep` overwrites `.cargo/config.toml`**: The story notes this explicitly. Using `cargo xtask man` (an alias) will fail in the RPM build environment; `cargo run -p xtask -- man` must be used instead.

6. **Vendored dependencies size**: `cargo vendor` produces hundreds of megabytes. If `vendor/` is not in `.gitignore`, it could be accidentally committed. The build script generates the vendor tarball on the fly and must not be run inside a CI environment that lacks network access to initially fetch crates (the vendor step requires internet access).

7. **`rpmlint` validation**: The acceptance criteria require `rpmlint netfyr.spec` to report no errors. Common lint failures include missing `%changelog`, duplicate `%license` directives across subpackages (handled by using `%license` in each `%files` section independently), and unowned directories.

8. **`%changelog` section**: Standard Fedora packaging guidelines require a `%changelog` section. Its absence will likely trigger an `rpmlint` error. The spec template in the story does not include one; implementer must add it.

9. **Macro expansion in spec comments**: Any mention of `%cargo_build`, `%cargo_prep`, etc. in RPM comments will be expanded unless doubled as `%%cargo_build`. Failure to escape will cause macro-not-found errors during spec parsing.
